# learn 팀 작업 폴더와 공유 파일

리드(스킬을 실행하는 세션), `learn-researcher`, `learn-writer`, `learn-verifier`가 같이 쓰는 작업 폴더의 구조와 파일 형식입니다. 메시지 형식은 보내는 쪽 에이전트 정의의 `## 팀 통신 프로토콜`에 있어요.

## 작업 폴더

`{ws}`는 세션 스크래치패드의 `learn-{slug}/`입니다(스크래치패드가 없으면 `$TMPDIR/learn-{slug}/`). vault 밖이라 Phase 1의 READ-ONLY 규칙과 부딪히지 않아요.

| 경로 | 쓰는 쪽 | 읽는 쪽 | 내용 |
|---|---|---|---|
| `sources.md` | researcher | writer, verifier | 고정 출처 목록. 해석 없이 식별자만 |
| `research.md` | researcher | writer, 리드 | 조사 노트: 중복 확인, 관측 순서, 스텝 후보, 분기 조건 위치, 처음 이해와 달랐던 것 |
| `src/{이름}/` | researcher | writer, verifier | 고정 태그로 받은 외부 소스. 실행하지 않음 |
| `example/` | researcher | verifier | 관측용 학습 예제. 회사 코드와 실 데이터 금지 |
| `obs/` | researcher | writer, verifier | 관측 로그 |
| `scenario-draft.md` | writer | verifier, 리드 | 시나리오 초안 ([scenario.md](scenario.md) 틀) |
| `verify-log.md` | verifier | 리드 | 회차별 검증 기록. 덧붙이기만 함 |
| `verify/` | verifier | verifier | 회차마다 떠 둔 대상 파일 사본. 다음 회차에서 바뀐 행을 찾는 기준 |

**verifier는 `research.md`를 열지 않습니다.** 리드도 verifier 프롬프트에 조사 요약, 작성 의도, 이전 판단을 넣지 않아요. verifier가 받는 출처는 `sources.md` 하나라서, 근거 칸을 조사 맥락 없이 출처만 보고 다시 판정하게 됩니다.

## sources.md

출처 하나가 한 행입니다. 근거 칸의 파일:줄, 관측, 명세 절은 모두 이 표의 어느 행으로 되짚을 수 있어야 해요.

```markdown
# 고정 출처: {주제}

| ID | 종류 | 이름 | 받는 곳 | 고정값 | 작업 폴더 경로 |
|---|---|---|---|---|---|
| S1 | 소스 | {저장소 또는 아티팩트} | {URL} | 태그 {tag}, 커밋 {sha} | src/{이름} |
| P1 | 명세 | {JVMS SE 21, RFC 9293} | {URL} | 절 {번호 목록} | - |
| O1 | 관측 | {무엇을 잡나} | `{실행 명령}` | 런타임 {버전} | example/, obs/{로그} |
```

- 소스 행의 커밋은 받은 체크아웃의 `git rev-parse HEAD`입니다. `*-sources.jar`나 raw 파일이면 버전이 들어간 URL을 고정값으로 써요.
- 관측 행의 명령은 `{ws}`에서 그대로 다시 돌릴 수 있게 적습니다.
- 해석, 요약, 스텝 번호는 적지 않아요. 그건 `research.md`의 몫입니다.

## verify-log.md

verifier가 회차마다 맨 끝에 절 하나를 덧붙입니다. 앞 회차의 절은 고치지 않아요.

```markdown
## {관문 | 재관문} {n}회차 ({YYYY-MM-DD HH:MM})

- 대상: {파일 경로 목록}
- 고정값 확인: {S1 커밋 일치 | 불일치(내용)}, {P1 열람}, {O1 재실행 결과 | 기록 로그 사용(이유)}
- 대조한 칸: {n} (소스 n, 관측 n, 명세 n, 같음 n, [확인 필요] n)
- 결과: {통과 | 불일치 n건 → learn-writer | 미해결 n건 → 리드}

| # | 파일 | 위치 | 주장 | 출처 근거 | 기대값 | 처리 |
|---|---|---|---|---|---|---|
| 1 | {파일} | {스텝, 절, 줄} | {지금 칸 값} | {확인한 위치와 그 줄이 하는 일} | {바꿀 값} | {대기, 반영, 반박 수용, 반박 기각} |
```

`처리`는 새 항목이면 `대기`이고, 다음 회차에서 직전 회차 항목을 다시 볼 때 결과를 적은 행을 새 절에 둡니다.

## 되돌림 회차

| 회차 | 하는 일 |
|---|---|
| 1 | 첫 대조. 불일치가 있으면 되돌림 1회 |
| 2 | writer 반영 뒤 재확인. 남으면 되돌림 2회 |
| 3 | 마지막 재확인. 남으면 verifier가 리드에게 미해결로 보고하고, 리드가 사용자에게 올림 |

재관문(Phase 2)은 회차를 1부터 다시 셉니다.
